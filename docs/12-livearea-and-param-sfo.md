# 12 — LiveArea & param.sfo

The difference between "a file in a folder" and "a game on the home screen".

---

## 1. param.sfo

Generated by `vita-mksfoex`, usually through CMake:

```cmake
set(VITA_APP_NAME "Game Name")
set(VITA_TITLEID  "XXXX00001")
set(VITA_VERSION  "00.10")
set(VITA_MKSFOEX_FLAGS "-d ATTRIBUTE2=12")
```

| Key | Meaning |
|-----|---------|
| `TITLE_ID` | 9 characters; first 4 are the publisher-style prefix |
| `TITLE` | display name in LiveArea |
| `APP_VER` | `00.00` … `99.99`, two-part |
| `ATTRIBUTE2` | flags; `12` is the usual homebrew value |
| `CATEGORY` | `gd` (game) for apps |
| `CONTENT_ID` | retail-style content id, only for signed content |
| `PSP2_DISPLAY_NAME` | livearea name, often same as `TITLE` |

`ATTRIBUTE2=12` combines "unsafe/homebrew" style bits. Emulators and ports ship
with it; without it, unsigned `eboot.bin` may refuse to start.

## 2. LiveArea assets

```
sce_sys/
  icon0.png                              128 x 128   bubble icon
  pic0.png                               background used in some views
  livearea/contents/
    bg0.png                              840 x 500   background
    startup.png                          280 x 158   startup image
    template.xml                         layout
```

A `template.xml` sets the frames (startup image, live area, gate) and their
positions. Emulators and larger ports add extra pages/links:

```xml
<livearea style="a1" format-ver="01.00" content-rev="1">
  <livearea-background>
    <image>bg0.png</image>
  </livearea-background>
  <gate>
    <startup-image>startup.png</startup-image>
  </gate>
</livearea>
```

## 3. Launch parameters

A bubble can pass arguments, which is how per-game custom bubbles work:

- LiveArea can be configured to pass a string; the app reads it:

```c
SceAppUtilAppEventParam event;
sceAppUtilReceiveAppEvent(&event);
if (event.type == 0x05) {
    char buffer[2048];
    sceAppUtilAppEventParseLiveArea(&event, buffer);
    if (strstr(buffer, "-config"))
        sceAppMgrLoadExec("app0:/configurator.bin", NULL, NULL);
}
```

That exact snippet is `soloader_init_all()`'s configurator redirect: the same
binary can boot as a game or as its own settings app.

For `&param=` style values, `sceAppMgrGetAppParam` returns the launch string
(Play! uses it to boot a disc image directly from a per-game bubble).

## 4. Relaunching yourself

`sceAppMgrLoadExec("app0:eboot.bin", NULL, NULL)` restarts the process. Legitimate
reasons:

- changing an initialisation-time GPU parameter (MSAA sample count, resolution
  class) — GXM render targets cannot be re-created with different samples
- switching between "game" and "configurator" roles

Always pass state through a file with a magic value and a freshness timestamp, and
validate it before trusting it (PCSX AwO: magic + 120-second window).

## 5. Installing

| Method | Use |
|--------|-----|
| VitaShell → VPK | end users |
| FTP into `ux0:app/<TITLEID>/` | development iteration |
| `vita-pack-vpk` in CI | releases |

VPK is a zip with `sce_sys/` and `eboot.bin` at the root. It must not be
re-compressed weirdly — plain deflate, no encryption.

## 6. Common mistakes

| Mistake | Result |
|---------|--------|
| title ID containing invalid characters | install fails silently |
| missing `icon0.png` | blank bubble |
| `ATTRIBUTE2` omitted | app may not launch |
| asset paths under `livearea/` wrong | broken LiveArea page |
| writing config into `app0:` | no-op or crash |
| 840×500 bg authored at 960×544 | stretched art |
